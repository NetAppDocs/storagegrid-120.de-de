= Überarbeiten Sie die ILM-Richtlinien für die Standortstilllegung in StorageGRID
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Im Schritt 3 (ILM-Richtlinien überarbeiten) des Assistenten zur Stilllegung von Standorten lässt sich feststellen, ob der Standort in einer ILM-Richtlinie referenziert wird.

.Bevor Sie beginnen
Sie haben ein gutes Verständnis dafür, wie link:../ilm/index.html["Objekte mit ILM verwalten"]. Sie sind mit der Erstellung von Speicherpools und ILM-Regeln sowie mit dem Simulieren und Aktivieren einer ILM-Richtlinie vertraut.

.Über diese Aufgabe
StorageGRID kann einen Standort nicht außer Betrieb nehmen, wenn eine ILM-Regel in einer beliebigen Richtlinie (aktiv oder inaktiv) auf diesen Standort verweist.

Falls eine ILM-Richtlinie auf den Standort verweist, den Sie stilllegen möchten, müssen Sie diese Richtlinien entfernen oder so bearbeiten, dass sie diese Anforderungen erfüllen:

* Alle Objektdaten sind vollständig geschützt.
* Beziehen Sie sich nicht auf den Standort, den Sie stilllegen.
* Keine Speicherpools verwenden, die sich auf den Standort beziehen oder die Option „Alle Standorte“ nutzen.
* Verwenden Sie keine Erasure-Codierungsprofile, die auf den Standort verweisen.
* Die Regel „2 Kopien erstellen“ aus StorageGRID 11.6 oder früheren Installationen sollte nicht verwendet werden.



CAUTION: Es sollte niemals eine ILM-Regel mit nur einer Kopie erstellt werden, um die Entfernung eines Standorts zu berücksichtigen. Eine ILM-Regel, die nur eine replizierte Kopie für einen beliebigen Zeitraum erstellt, setzt Daten dem Risiko eines dauerhaften Verlusts aus. Wenn nur eine replizierte Kopie eines Objekts existiert, geht dieses Objekt verloren, falls ein Storage Node ausfällt oder einen schwerwiegenden Fehler aufweist. Auch während Wartungsarbeiten wie Upgrades ist der Zugriff auf das Objekt vorübergehend nicht möglich.


TIP: Wenn Sie eine verbundene Site außer Betrieb nehmen, muss berücksichtigt werden, wie StorageGRID die Objektdaten an der Site verwalten soll, die entfernt werden soll. Abhängig von Ihren Datenschutzanforderungen können neue Regeln vorhandene Objektdaten an andere Sites verschieben oder zusätzliche, nicht mehr benötigte Objektkopien löschen.

Wenden Sie sich an den technischen Support, wenn Sie Hilfe bei der Erstellung einer neuen Richtlinie benötigen.

.Schritte
. Ab Schritt 3 (Überarbeitung der ILM-Richtlinien) lässt sich feststellen, ob ILM-Richtlinien auf den zur Stilllegung ausgewählten Standort verweisen.
. Falls keine Richtlinien aufgeführt sind, mit *Weiter* zu link:step-4-remove-ilm-references.html["Schritt 4: ILM Referenzen entfernen"] wechseln.
. Falls eine oder mehrere _aktive_ ILM-Richtlinien aufgeführt sind, sollte jede vorhandene Richtlinie geklont oder neue Richtlinien erstellt werden, die nicht auf den stillzulegenden Standort verweisen:
+
.. Wählen Sie den Link für die Richtlinie in der Spalte „Richtlinienname“.
+
Die Detailseite der ILM-Richtlinie wird in einem neuen Browser-Tab angezeigt. Die Seite zur Stilllegung des Standorts bleibt im anderen Tab geöffnet.

.. Diese Richtlinien und Anweisungen sind bei Bedarf zu beachten:
+
*** Arbeiten mit ILM Regeln:
+
**** link:../ilm/creating-storage-pool.html["Einen oder mehrere Speicherpools erstellen"]die sich nicht auf die Website beziehen.
**** link:../ilm/working-with-ilm-rules-and-ilm-policies.html["Regeln bearbeiten oder ersetzen"]die sich auf die Website beziehen.
+

NOTE: Die Regel *2 Kopien erstellen* sollte nicht ausgewählt werden, da diese Regel den Speicherpool *Alle Speicherknoten* verwendet, was nicht zulässig ist.



*** Arbeiten mit ILM Richtlinien:
+
**** link:../ilm/working-with-ilm-rules-and-ilm-policies.html#clone-ilm-policy["Eine bestehende ILM Richtlinie klonen"] oder link:../ilm/creating-ilm-policy.html["eine neue ILM Richtlinie erstellen"].
**** Sichergestellt ist, dass die Standardregel und andere Regeln nicht auf die Site verweisen.
+

CAUTION: Sie müssen bestätigen, dass die ILM-Regeln in der richtigen Reihenfolge sind. Bei der Aktivierung der Richtlinie werden neue und bestehende Objekte von oben beginnend in der aufgelisteten Reihenfolge durch die Regeln ausgewertet.





.. Testobjekte einlesen und die Richtlinie simulieren, um sicherzustellen, dass die richtigen Regeln angewendet werden.
+

CAUTION: Fehler in einer ILM-Richtlinie können zu unwiederbringlichem Datenverlust führen. Die Richtlinie sollte sorgfältig überprüft und simuliert werden, bevor sie aktiviert wird, um sicherzustellen, dass sie wie vorgesehen funktioniert.

+

CAUTION: Bei Aktivierung einer neuen ILM-Richtlinie verwendet StorageGRID diese zur Verwaltung aller Objekte, einschließlich vorhandener und neu ingestierter Objekte. Vor der Aktivierung einer neuen ILM-Richtlinie sollten alle Änderungen an der Platzierung vorhandener replizierter und mit Erasure Coding versehener Objekte überprüft werden. Eine Änderung des Speicherorts eines vorhandenen Objekts kann zu vorübergehenden Ressourcenproblemen führen, wenn die neuen Platzierungen bewertet und implementiert werden.

.. Die neuen Richtlinien werden aktiviert, während die alten Richtlinien nun inaktiv sind.
+
Wenn Sie mehrere Richtlinien aktivieren möchten, link:../ilm/creating-ilm-policy.html#activate-ilm-policy["Führen Sie die Schritte zum Erstellen von ILM Policy-Tags aus."].

+
Wenn Sie eine verbundene Site außer Betrieb nehmen, beginnt StorageGRID mit dem Entfernen der Objektdaten von der ausgewählten Site, sobald Sie die neue ILM-Richtlinie aktivieren. Das Verschieben oder Löschen aller Objektkopien kann mehrere Wochen dauern. Obwohl eine Außerbetriebnahme einer Site auch dann sicher gestartet werden kann, wenn noch Objektdaten an der Site vorhanden sind, wird das Verfahren schneller und mit weniger Unterbrechungen sowie Leistungseinbußen abgeschlossen, wenn die Daten vor dem eigentlichen Außerbetriebnahmevorgang von der Site verschoben werden (durch Auswahl von *Außerbetriebnahme starten* in Schritt 5 des Assistenten).



. Jede _inaktive_ Richtlinie kann bearbeitet oder entfernt werden, indem zunächst der Link für die jeweilige Richtlinie ausgewählt wird, wie in den vorherigen Schritten beschrieben.
+
** link:../ilm/working-with-ilm-rules-and-ilm-policies.html#edit-ilm-policy["Die Richtlinie bearbeiten"] Es bezieht sich also nicht auf den Standort, der stillgelegt werden soll.
** link:../ilm/working-with-ilm-rules-and-ilm-policies.html#remove-ilm-policy["Eine Richtlinie entfernen"].


. Nachdem Sie die Änderungen an den ILM-Regeln und Richtlinien abgeschlossen haben, sollten in Schritt 3 (ILM-Richtlinien überarbeiten) keine weiteren Richtlinien mehr aufgeführt sein. *Weiter* auswählen.
+
Schritt 4 (ILM-Referenzen entfernen) erscheint.
