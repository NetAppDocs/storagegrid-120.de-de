= Stellen Sie Prometheus-Metriken wieder her, wenn Sie einen nicht-primären StorageGRID-Admin-Knoten wiederherstellen
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Optional ist es möglich, die von Prometheus auf einem ausgefallenen nicht primären Admin-Node gespeicherten historischen Metriken beizubehalten.

.Bevor Sie beginnen
* Der wiederhergestellte Admin-Node ist installiert und betriebsbereit.
* Das StorageGRID System umfasst mindestens zwei Admin-Nodes.
* Sie haben die  `Passwords.txt` Datei.
* Sie besitzen die Bereitstellungspassphrase.


.Über diese Aufgabe
Wenn ein Admin-Node ausfällt, gehen die in der Prometheus-Datenbank auf dem Admin-Node gespeicherten Metriken verloren. Bei der Wiederherstellung des Admin-Node wird während des Softwareinstallationsprozesses eine neue Prometheus-Datenbank erstellt. Nach dem Start des wiederhergestellten Admin-Node werden Metriken erfasst, als ob eine Neuinstallation des StorageGRID Systems durchgeführt worden wäre.

Wenn Sie einen nicht primären Admin-Knoten wiederhergestellt haben, können die historischen Metriken wiederhergestellt werden, indem die Prometheus Datenbank vom primären Admin-Knoten (dem _Quell-Admin-Knoten_) auf den wiederhergestellten Admin-Knoten kopiert wird.


NOTE: Das Kopieren der Prometheus Datenbank kann eine Stunde oder länger dauern. Einige Grid Manager Funktionen sind nicht verfügbar, solange die Dienste auf dem Quell Admin Node angehalten sind.

.Schritte
. Anmeldung am Quell-Admin Node:
+
.. Geben Sie den folgenden Befehl ein: `ssh admin@_grid_node_IP_`
.. Geben Sie das in der  `Passwords.txt` Datei aufgeführte Passwort ein.
.. Geben Sie den folgenden Befehl ein, um zu root zu wechseln: `su -`
.. Geben Sie das in der  `Passwords.txt` Datei aufgeführte Passwort ein.


. Vom Quell-Admin-Node aus den Prometheus-Dienst stoppen: `service prometheus stop`
. Führen Sie die folgenden Schritte auf dem wiederhergestellten Admin-Node aus:
+
.. Anmeldung am wiederhergestellten Admin-Knoten:
+
... Geben Sie den folgenden Befehl ein: `ssh admin@_grid_node_IP_`
... Geben Sie das in der  `Passwords.txt` Datei aufgeführte Passwort ein.
... Geben Sie den folgenden Befehl ein, um zu root zu wechseln: `su -`
... Geben Sie das in der  `Passwords.txt` Datei aufgeführte Passwort ein.


.. Den Prometheus Service stoppen: `service prometheus stop`
.. Fügen Sie den privaten SSH-Schlüssel zum SSH-Agenten hinzu. Geben Sie Folgendes ein:``ssh-add``
.. Geben Sie das im  `Passwords.txt`-Datei aufgeführte SSH-Zugriffspasswort ein.
.. Die Prometheus Datenbank vom Quell-Admin-Knoten auf den wiederhergestellten Admin-Knoten kopieren: `/usr/local/prometheus/bin/prometheus-clone-db.sh Source_Admin_Node_IP`
.. Wenn Sie dazu aufgefordert werden, drücken Sie *Eingabetaste*, um zu bestätigen, dass die neue Prometheus Datenbank auf dem wiederhergestellten Admin-Knoten zerstört werden soll.
+
Die ursprüngliche Prometheus Datenbank und ihre historischen Daten werden auf den wiederhergestellten Admin Node kopiert. Nach Abschluss des Kopiervorgangs startet das Skript den wiederhergestellten Admin Node. Der folgende Status erscheint:

+
Datenbank geklont, Dienste werden gestartet

.. Wenn kein passwortloser Zugriff auf andere Server mehr erforderlich ist, sollte der private Schlüssel aus dem SSH-Agenten entfernt werden. Eingabe:``ssh-add -D``


. Der Prometheus-Dienst auf dem Quell-Admin-Knoten wird neu gestartet..`service prometheus start`
